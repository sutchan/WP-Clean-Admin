## 代码审查（2026-08-08 第三次）

用户要求"审查项目"。输出审计报告：`wpcleanadmin/assets/docs/审计报告_20260808.md`。

### 关键发现（P0-P3）
- **P0-1 严重**：`includes/class-wpca-ajax.php` 声明空实现 IDE stub（`wp_verify_nonce(){}`），
  dispatcher 级未真正调用 `check_ajax_referer`/`current_user_can`，非 WP 环境下 nonce 校验形同虚设。
- **P0-2 严重**：action 冲突 `wpca_dashboard_save` 同时被 dashboard 模块（存原始 clean）与
  settings-page.js（实为全局设置）使用，与 Settings 模块 `wpca_settings_save`（存 merged 结构）
  职责重叠、数据结构不一致。建议删除 dashboard 的该 action，统一走 Settings。
- **P1-1**：原型 `Module_Base::register_ajax` 直接 `add_action`，未串联 `Gateway_Base::dispatch` 守卫链，
  与规范"统一网关"声明矛盾。
- **P1-2**：前端 app.js 多处 `innerHTML` 拼接动态文本（metric/count/label/advice），存在 XSS 风险，须转义。
- **P1-3**：测试覆盖率远低于 80%，本机无 PHP CLI 未实跑 `composer test`。
- **P2**：旧式类与模块并存；设计规范与 api.md Dashboard 职责错位；dashboard.html/settings-page.html 双入口重复。
- **P3**：database 模块白名单校验为 TODO；app.js `MOCK_NONCE` 缺环境检测。

### 结论
主代码（1.8.2）历史修复到位，但原型+模块化架构引入 P0 级安全/一致性回退，优先修 P0-1/P0-2/P1-1。
