# WP Clean Admin 设计规范（高保真）

版本：1.8.3 基线
最后更新：2026-08-08（与 openspec 同步修订）

## 1. 产品定位与信息架构

WP Clean Admin 是 WordPress 后台清理与优化插件，目标用户为站点管理员。
信息架构（IA）以**单一顶级菜单**为入口，下设 7 个一级功能页（与模块一一对应）：

```
WP Clean Admin（顶级菜单，slug: wp-clean-admin）
├─ 仪表盘 Dashboard      总览 + 一键体检        Module_Dashboard
├─ 清理 Cleanup          数据库/媒体/评论/内容清理  Module_Cleanup
├─ 性能 Performance       资源与加载优化          Module_Performance
├─ 安全与菜单 Security    菜单定制 + 权限 + 登录优化 Module_Security
├─ 数据库 Database        表管理 + 备份/恢复       Module_Database
├─ 诊断 Diagnostics       环境检测 + 报告          Module_Diagnostics
└─ 设置 Settings          全局配置（general/performance/menu 三组） Module_Settings
```

设计原则：
- 每页左侧为功能导航 tab（`.wpca-nav`），右侧为内容区（WP 后台惯用布局）
- 危险操作（删除/重置/优化）必须二次确认 modal + 显示影响范围
- 所有写操作经 AJAX 网关（`Gateway_Base`，nonce + capability 双校验）
- 左侧导航第 7 项为「设置」，独立保存全局配置，区别于各功能页的局部操作

- 代码/数据：等宽字体 `12px`

### 2.3 响应式
- 断点：960px（导航转抽屉）、600px（操作按钮堆叠、统计双列）

## 4. 交互规范

### 4.1 AJAX 数据流
```
前端 submit ──► FormData(含 _wpnonce) ──► Gateway_Base.dispatch()
  ├─ wp_verify_nonce(_wpnonce, 'wpca_ajax_nonce')  → 失败 403 invalid_nonce
  ├─ current_user_can('manage_options')            → 失败 403 forbidden
  └─ call_user_func(handler) ──► wp_send_json_success/error
前端收到响应 ──► 更新 UI / 显示 toast
```
- 加载态：按钮 `disabled`（`.wpca-btn:disabled` 半透明）
- 失败：`.wpca-toast--error` + 表单/开关回滚
- 成功：`.wpca-toast--success` + 数据刷新

### 4.2 危险操作二次确认
- 删除/清理类按钮点击 → `.wpca-modal` 弹出，正文显示"将影响 N 条记录"
- 确认按钮 `#wpca-modal-confirm` 触发回调后才发起 AJAX；Esc / 点遮罩 / 取消关闭

### 4.3 空状态与错误态
- 无数据：`.wpca-empty`（图标 + 文案，如体检前占位）
- 加载失败：`.wpca-toast--error` + 控制台记录，不阻断其他面板

## 5. 可访问性（WCAG AA）

- 所有交互元素可键盘聚焦，焦点环 `--wpca-primary`
- 表单 label 关联 input（`for`/`id` 或包裹）
- 状态变更用 `aria-live="polite"` 区域播报
- 颜色不作为唯一信息载体（徽标配文字）
- 弹窗 `role="dialog"` + `aria-modal="true"` + Esc 关闭 + 焦点陷阱

## 6. 编码与目录规范

- 命名空间：`WPCleanAdmin\Modules\<Domain>\Classes\Module_<Name>`
- 模块继承 `Module_Base`；AJAX 经 `Gateway_Base`
- 所有输出 `esc_*`；所有输入 `sanitize_*`；SQL `$wpdb->prepare`
- 文件头标注 `@package` / `@version`；中文注释关键逻辑

## 8. AJAX 接口标准（权威定义）

所有模块 AJAX 必须经由 `Gateway_Base::register()`，统一以下契约，**禁止裸 `add_action('wp_ajax_*')`**。

### 8.1 请求契约
- action：`wp_ajax_<action>`（后端注册名），请求体 `action` 字段值为 `<action>`
- nonce 字段名：**固定 `_wpnonce`**（前端经 `wp_nonce_field('wpca_ajax_nonce', '_wpnonce')` 注入）
- nonce action 名：**`wpca_ajax_nonce`**（全局唯一，所有 handler 共用）
- 权限：`current_user_can('manage_options')`（公开 handler 除外）

### 8.2 响应契约（成功）
```json
{ "success": true, "data": { /* 业务负载，结构见第 9 节 */ } }
```

### 8.3 响应契约（失败）
```json
{ "success": false, "data": { "message": "<code>" } }
```
HTTP 状态码与错误码映射：

| code | HTTP | 含义 |
|------|------|------|
| `invalid_nonce` | 403 | nonce 校验失败 |
| `forbidden` | 403 | 权限不足（capability 校验失败） |
| `unknown_action` | 404 | action 未注册 |
| `unknown_task` / `invalid_option` | 400 | 业务参数非法 |

### 8.4 前端调用封装
```js
api(action, extra, mockHandler) // 内部 FormData 自动附加 action + _wpnonce
```

## 9. 数据结构（Schema）

### 9.1 各模块业务数据结构
| 模块 | 关键字段 | 类型 |
|------|----------|------|
| Dashboard.metrics | `{label, count, level}` | level ∈ success/warning/danger/info |
| Cleanup.task | `{id, label, count, risk}` | risk ∈ low/medium/high |
| Performance.option | `{id, label, on}` | on: bool |
| Security.menu | `{slug, label, visible, system}` | system: bool |
| Database.table | `{name, rows, size, overhead}` | size/overhead: string |
| Diagnostics.check | `{label, value, status, advice}` | status ∈ success/warning/danger |
| Settings.config | `{general, performance, menu}` | 见 9.2 |

### 9.2 设置页数据结构（Settings）
```ts
type SettingsConfig = {
  general: { keep_revisions: number; auto_cleanup: boolean };
  performance: { disable_emojis: boolean; lazy_images: boolean; minify_html: boolean };
  menu: { [slug: string]: boolean }; // slug -> visible
}
```
- 写入前递归 `sanitize_settings`（见 Module_Base）
- 存储于 `wp_options` 键 `wpca_settings`（序列化数组）
- 菜单可见性另存 `wpca_menu_visibility`

## 10. 业务规则

- **R1 安全基线**：所有写操作 = nonce 校验 + capability 校验 + 输入 sanitize + 输出 esc_*。
- **R2 危险操作**：删除/重置/优化/清理必须 modal 二次确认，确认前不得发起 AJAX。
- **R3 菜单可见性**：system=true 的菜单（index/themes/plugins/users/options）默认可见且不可隐藏（防锁死后台）。
- **R4 设置合并**：保存设置时合并默认值，避免缺失键导致读取报错。
- **R5 进度反馈**：长任务（体检/清理/备份）显示 `.wpca-progress` 进度条，禁止无反馈等待。
- **R6 状态播报**：所有异步结果经 `aria-live` toast 区域，颜色不作为唯一状态载体。
